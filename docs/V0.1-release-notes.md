# CasioSync V0.1 R1

Released 13 October 2026 (Australia/Brisbane). First Casio-only release, derived from Time Transmitter V4.16 R1; the original repository remains unchanged.

## Changes

- Removed every LF/atomic-clock encoder, carrier/envelope task and timer, transmitter output, station/transmission schedule, radio control and LF API. The UI now has seven Casio-focused sidebar pages.
- Carried over the working GW-BX5600 MIP exchange, font choice, battery estimate, pairing/manual sync, four persistent profiles, Always Wait and recurring BT slots. Both V4.16 schedule fixes are retained.
- Retained Wi-Fi provisioning, AP/reconnection recovery, NTP trust/holdover/adaptive sync, independent daily Wi-Fi browser-access schedule, idle-controller power saving, h/m/s uptime, BT-only 24-hour success LED, four-entry RAM history and optional compact first-success-per-Brisbane-day status retention. Crash dumps remain default Off; no continuous flash logs or periodic maintenance reboot.
- Added a bounded catalog of 122 exact protocol candidates (BX, 118 Standard and three experimental MTG Analogue). Corrected Standard TIME to the captured 11-byte format; unrelated MIP/health/legacy/unknown models do not select a silent fallback. Catalog membership is not physical watch validation.
- Added optional per-watch preferences for 119 BX/Standard capability candidates: five alarms, hourly chime, countdown duration, 12/24-hour format, button tone, auto light, watch power saving, light duration, date order, weekday language and automatic adjustment/minute after the hour. Default Off/Keep; bound to watch identity, saved only on explicit user changes, applied before TIME with selective record merges and readback. Unsupported layouts are refused and results remain separate from time delivery. Analogue optional settings are unavailable in this release.
- Added independent CasioSync CRC settings/status/options files; invalid records are preserved and ignored safely. Hardened grouped config rollback, strict slot inputs, deferred Wi-Fi credential reconnect and Wi-Fi access timezone allocation/rollback. Corrected new-feature response-channel routing and watch-options CRC padding during prepublication review.
- Added actual compiled Node32s and ESP32-C3 SuperMini packages with chip/partition checks, hashes, matching compressed ELF symbols and flashing instructions. Node32s GPIO2 LED is active-high; C3 SuperMini GPIO8 is active-low, with USB CDC enabled. Packages are also tracked under `compiled/V0.1-R1/`.
- Added current changelog at the top of the IDE sketch, CasioSync GitHub links, model/feature evidence docs and preserved authorship/license notices.

## Dependencies and installation

Arduino-ESP32 **3.3.12**, ArduinoJson **6.21.5**, bundled NimBLE-Arduino **2.5.1-radioclock.1**, RadioBoundedWebServer **3.3.12-radioclock.1**, and RadioCrashDumpGate **1.0.1**. The crash gate adds the source-only `src/esp32c3` linker metadata marker; its C++ gate implementation is unchanged. Replace the old helper folder with this complete version, retaining both MCU markers. No compiled library archive is required.

Open `firmware/CasioSync_V0_1/CasioSync_V0_1.ino`, keeping every companion header and partition table with it. A fresh device provides `CasioSync_XXXXXX`, password `12345678`, at `http://192.168.4.1`. CasioSync uses its own settings schema, so provision it separately from Time Transmitter. Routine upgrades do not require erase-all. Read the board-specific package README for exact offsets; the application-only upgrade image goes at `0x10000`.

## Validation status

A fresh independent [embedded source review](V0.1-review.md), focused native captured-packet/BT scheduling/clock/LED checks, two production notification/executor sanitizer cases, and a desktop/watch/phone render review completed before publication. Both board compilations and the architecture-specific actual panic-gate/SNTP-dispatch ELF checks passed; application images fit their shipped partition layout. Detailed build/image evidence is retained in `docs/build-evidence/v0.1/` and each package manifest.

**Full post-publication suite: pending.** Source and compiled packages are published first, following the requested release order. This section will be updated with the actual suite result; a discovered issue requires a reviewed, published numbered revision before repeating the full checks.

No physical ESP32 or watch is attached to this cloud environment. The inherited BX time-sync evidence does not validate every new model/setting. Optional groups can partly apply, and stalled ATT work can abort the whole session at the bounded deadline. Feature readback confirms requested fields, not the physical display. [Model limits](WATCH_SUPPORT.md) and [feature layouts/ranges](WATCH_FEATURES.md) distinguish source-backed candidates from device acceptance.
