# V0.1 R3 embedded reliability and package review

Read-only independent review on 13 October 2026, Brisbane time. The reviewer changed only this document and did not run compilation, host tests or the full suite.

## Production scope

The R3 firmware delta from published R2 contains the newest-first R3 changelog, the build label and the regenerated embedded UI version labels. Bluetooth packets, callback/task ownership, deadlines, scheduling, Wi-Fi/NTP handling, settings persistence and flash-write policy remain unchanged. Companion headers, partition layout and dependency sources are unchanged. The [independent R1 source review](V0.1-review.md) therefore continues to apply to production behavior, including its corrections and physical-testing limits.

## Package source enumeration

The earlier package manifests included two ignored local build partition CSV paths that were absent from the published source archive. The R3 packager replaces recursive directory scanning with NUL-delimited `git ls-files --cached --others --exclude-standard` enumeration restricted to `firmware`, `libraries` and `ui`. It retains the existing source suffixes and `library.properties` selection, checks that each file exists and hashes its bytes. Ignored untracked build output is excluded; tracked files remain eligible even when ignore rules match them. NUL separation avoids ambiguity in names containing spaces or line breaks.

This changes manifest provenance, rather than application behavior. Image copying, chip-ID validation, the shipped 3 MB application partition check, bounded factory-image construction, symbol compression, offsets and artifact hashes are unchanged. The release owner must include the enumerated nonignored source files in the published commit and compare the final manifests against the actual downloaded source and board archives. Both boards must be rebuilt with R3 labels and paired with their own matching ELF; no R2 binary is represented as an R3 build.

## Schedule fixture correction

R2's post-publication suite stopped because the schedule host fixture lacked declarations/mocks required by the retained grouped configuration transaction. The corrected fixture continues extracting the complete actual production commit lambda. It adds credential/display/Wi-Fi/listening state and side-effect mocks, rather than replacing the handler with a simplified implementation.

Read-only inspection confirmed assertions for grouped failed-save rollback, allocation failure at either String reserve, successful durable rearming of exactly all four slots, timezone application and deferred credential reconnect only after a successful save, and preservation of unchanged BT/display settings and an existing password. Production code was not changed to accommodate the fixture. The focused test agent reported all three schedule cases and both unchanged Wi-Fi/NTP cases passing under the existing sanitizer harness; their logs were inspected. This reviewer did not execute those tests. The full suite remains a post-publication step under the user's release order.

## Limits and current conclusion

No production or package-enumeration blocker was identified in the reviewed R3 delta. Final release evidence must record the frozen-source build/ELF/manifest checks and actual focused and post-publication suite results, rather than infer success from this source review.

No physical board or watch was tested by this reviewer. The inherited user's BX time-sync evidence does not validate every new watch candidate or optional setting. Separate setting groups may partly apply, and a stalled ATT operation can exhaust the bounded session deadline. Matching settings readback does not verify the watch's physical display. These limits and the bounded-memory, persistence and recovery analysis in the R1 review remain applicable.
